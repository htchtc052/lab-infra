# Timeweb: пауза, возврат, что переживает что

## Пауза — 240 ₽ вместо 1200 ₽

Способ остановить расходы, сохранив всю настройку. Работает только при
**положительном балансе**: при нулевом всё удаляется, см. ниже.

**1. Остановить стек.** Иначе база попадёт в снимок посреди записи.

```bash
ssh root@<IP> 'cd /srv/lab/infra && docker compose stop'
```

**2. Снять образ.** Сервер → Образы → создать. Диск занят около 10 ГБ, хранение
4 ₽/ГБ в месяц.

**3. Удалить сервер.** Почасовые списания прекращаются.

**4. Адрес не удалять.** Публичный IP закреплён за аккаунтом, а не за сервером,
и переживает его удаление. Он тарифицируется и без привязки — 200 ₽ в месяц, и
это плата за то, что при возврате не придётся трогать ни DNS, ни PTR.

**5. Оставить деньги на балансе** — на образ и адрес, с запасом на весь срок
паузы. Это единственное, что отделяет паузу от потери всего.

## Возврат

Создать сервер из образа (Образы → создать сервер), привязать **тот же** IP.
Дальше:

```bash
ssh root@<IP> 'cd /srv/lab/infra && docker compose up -d'
```

DNS, PTR и DKIM менять не нужно — они привязаны к адресу, который сохранился.

## Неуплата — не пауза

При нулевом балансе аккаунт блокируется, и через **7 дней автоматически
удаляются серверы, облачные сервисы и все связанные данные, включая образы**.
Публичные IP относятся к тем же связанным ресурсам.

То есть просто перестать платить — значит потерять и снимок, и адрес. Уцелеют
только репозитории на GitHub, и разворачивать придётся с нуля на новом IP.

## Что переживает всё

Домен и его DNS-зона. Поддержка подтвердила: домены, зарегистрированные через
Timeweb, при блокировке аккаунта не снимаются с делегирования, файл зоны
остаётся без изменений. Автоматически удаляются только домены, зарегистрированные
не у них.

То есть записи уцелеют, но будут указывать на несуществующий адрес.

## Если адрес всё же потерян

Новый сервер получит другой IP, и правятся четыре места:

| где | что |
|---|---|
| DNS → A | `photo`, `photo-api`, `mail` |
| DNS → TXT на корне | SPF содержит адрес числом: `v=spf1 ip4:<IP> …` |
| Сеть → Публичные IP → PTR | обратная зона на `mail.proclouds.ru` |

Сначала A-запись `mail`, потом PTR: Gmail проверяет, что имя из PTR разрешается
обратно в тот же адрес. Без этого письма отклоняются с `550-5.7.25`.

## Ключ DKIM

TXT-запись `mail._domainkey` соответствует приватному ключу в томе
`postfix_dkim`. С образом том сохраняется. Потеряется — `boky/postfix`
сгенерирует новый ключ, и записи разойдутся: письма будут уходить, но не
проходить проверку подписи. Новое значение:

```bash
docker compose exec postfix cat /etc/opendkim/keys/proclouds.ru.txt
```

Селектор — `mail`, несмотря на `s=email` внутри значения: `s=` означает тип
сервиса, а имя записи задаёт `SigningTable`.

## Прочее по этому хостингу

- Порты 25, 465, 587, 2525 закрыты по умолчанию; разблокируются через поддержку.
- Docker Hub отдаёт `429` анонимным клиентам. В `/etc/docker/daemon.json`
  прописано зеркало `https://dockerhub.timeweb.cloud`.
